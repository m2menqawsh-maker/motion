# Plugin Architecture & Boundary Specification

## 1. Overview & Portability Model

The Super Video Maker plugin located at:
```text
.agents/plugins/super-video-maker-plugin/
```
operates under the **`REPO_COUPLED`** portability model.

It is an integration and discovery layer designed specifically to operate within this video production repository. It is **NOT** a standalone duplicate or shadow copy of the application runtime.

## 3. Structural & Operational Invariants

1. **Zero-Mirror Principle**: The plugin MUST NOT maintain mirrors or duplicates of root canonical scripts, templates, recipes, references, security configs, or ground-truth catalogs.
2. **Canonical Asset Index**: `ground-truth/ASSET_INDEX.json` is generated by `scripts/generators/build_asset_index.py` at the repository root. All consumers (`scripts/gates/asset_gate.py`, `common-tools-mcp/utils/cache_ops.py`) must resolve and read this root file exclusively.
3. **Dynamic Path Resolution**: Tools and MCP servers hosted inside the plugin resolve the repository root dynamically (by walking up directory parents until repository boundaries are reached or checking `SVM_DATA_DIR`). They do not hardcode stale or divergent subpaths.
4. **Agent Command Wrapping**: Plugin commands in `commands/` are thin user/agent-facing wrappers that strictly invoke `scripts/pipeline.py`. They never implement parallel pipelines or bypass canonical gates.
