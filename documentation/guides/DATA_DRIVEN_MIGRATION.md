# دليل الهجرة من الواجهة البرمجية إلى الاعتماد على البيانات (Data-Driven Migration)

هذا الدليل يشرح الانتقال الاستراتيجي للمشروع في المراحل من 0 إلى 7، من الاعتماد على توليد الأكواد (Code-Driven) في Remotion إلى الاعتماد الكامل على هياكل البيانات (Data-Driven).

## الهدف
- **سابقاً**: كل فيديو كان يحتاج لإنشاء مجلد مليء بملفات `Scene.tsx` وأكواد React وتوليدها لكل مشروع جديد.
- **حالياً (v5.0)**: المشروع أصبح "حتمي البناء" (Deterministic Build). ملف Composition واحد كفيل برسم أي فيديو من خلال قراءة ملفات `JSON` فقط دون تعديل أي كود.

## الهياكل الأساسية (JSON Contracts)
1. **`project.json`**: إعدادات الإخراج (FPS، الأبعاد، لغة المشروع).
2. **`brand.json`**: الهوية البصرية (الخطوط، الألوان الأساسية والثانوية، الشعار).
3. **`manifest.json`**: سجل الأصول الذي يضمن عدم استخدام ملفات غير موجودة أو غير معتمدة.
4. **`blueprint.json`**: المخطط الهيكلي (Sequence) الذي يربط القوالب بالنصوص والإعدادات الفردية لكل مشهد بالإضافة إلى مسارات الصوت (Voiceover, BGM).
5. **`overrides.json`**: التجاوزات اليدوية لتعديل خصائص دقيقة لمشهد معين (مثل تغيير حجم الخط أو موضع العنصر).
6. **`state.json`**: يوثق حالة المشروع ومراحل سير العمل وبوابات الموافقة (Media, Plan, Code, Render).
7. **`04_timings.json`**: توقيتات متزامنة على مستوى الكلمات (لاستخدامها في قوالب كـ Karaoke Captions).

## المشروع المرجعي (Demo Brand)
تم توفير المجلد `projects/demo_brand` كمشروع مرجعي (Reference Project) يحتوي على وسائط حقيقية وعقود بيانات سليمة (تم اجتيازها لفلاتر الـ Schemas). 
يمكن من خلاله استخدام أوامر مثل `scripts/e2e_data_render.py` لاختبار Pipeline الإخراج من البداية حتى الـ Render النهائي لملف MP4 دون الحاجة للتدخل البرمجي.

## الانتقال للواجهة الرسومية (GUI)
هذه الهيكلة مهّدت الطريق لبناء تطبيقات ويب تتخاطب مباشرة مع مسارات الـ API (المطورة في المرحلة 6).
- واجهة المستخدم تُنشئ وتُحدث ملفات الـ JSON فقط.
- الـ Player يقرأ `blueprint.json` عبر `loadProjectData.ts`.
- التصدير (Render) يتم بسلاسة تامة.
