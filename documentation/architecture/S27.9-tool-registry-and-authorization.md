# S27.9 Tool Registry + Authorization + Domain Tool Layer

## 1. Overview
The S27.9 subsystem establishes a secure, deterministic, and strongly-typed boundary enabling untrusted AI models and agents to request controlled system actions without granting them direct access to domain internals, databases, filesystem paths, lifecycle mutation mechanisms, or QC/approval gates.

```text
Untrusted AI / Model Completion
              ↓
           ToolCall (untrusted parameters)
              ↓
        ToolDispatcher
              ↓
  1. ToolRegistry lookup (reject unknown)
  2. Enabled check (reject disabled)
  3. Input Schema Validation (extra='forbid', reject forged identity)
  4. ToolAuthorizationPolicy (server-side, cross-tenant check)
  5. Bounded Timeout Execution
              ↓
     Domain Tool Adapter (thin mapper)
              ↓
    Existing Domain Service (ProjectService, AssetService, RunService, etc.)
              ↓
    Output Contract Validation
              ↓
     ToolAuditRecorder (sanitized audit entry)
              ↓
    Canonical ToolResult (SUCCESS / ERROR)
```

## 2. Binding Security Invariants

### 2.1 Trusted Identity Isolation (ADR-004 DEC-06.6)
Untrusted LLM completions and `ToolCall` parameters are strictly forbidden from supplying authoritative identity fields:
- `workspace_id`
- `tenant_id`
- `user_id`
- `actor_id`
- `principal_id`
- `role` / `roles`
- `permission` / `permissions`
- `approved_by`
- `is_admin` / `is_owner`

Identity is injected exclusively server-side via `TrustedToolExecutionContext` derived from authentic server session tokens (`Principal` / `TenantContext`).

### 2.2 Pre-Execution Authorization Order
Authorization is evaluated strictly **BEFORE** invoking any domain adapter:
```text
Validate Input Schema
         ↓
Resolve Server-Side Trusted Context
         ↓
Evaluate ToolAuthorizationPolicy
         ↓
Execute Domain Adapter
```
If an authorization check fails (cross-tenant access, missing permissions, disabled tool, revoked role):
- Execution aborts immediately.
- The Domain Adapter is never invoked (`invocation_count = 0`).
- Zero side effects occur (state unchanged, no jobs created, no artifacts written).

### 2.3 Strict Domain Service Mediation
The `ai/tools/` layer contains no persistence logic or filesystem access.
- ❌ No `open()`, direct `Path("projects/...")` mutation, or shell execution.
- ❌ No raw SQL (`SELECT`, `INSERT`, `UPDATE`, `DELETE`) or direct ORM session bypass.
- ❌ No direct lifecycle mutation (`state.lifecycle_state = ...`).
- ❌ No QC approval, gate bypass, or human review override tools.
- ❌ No vendor provider SDK imports (`openai`, `anthropic`, `gemini`, etc.).

All actions are strictly delegated to existing, governed domain services:
- `ProjectService`
- `AssetService`
- `PipelineService`
- `RunService`
- `DomainArtifactService`
- `ReviewService`

| `start_run` | `RUN_CONTROL` | `run:execute` | `RunService.create_run` | `IDEMPOTENT_BY_KEY` | 30.0s |

| `get_qc_report` | `READ_ONLY` | `qc:view` | `DomainArtifactService.read_artifact` & `ReviewService.get_review_status` | `IDEMPOTENT_READ` | 15.0s |

## 4. Side-Effect Taxonomy
- `READ_ONLY`: Queries authoritative domain state without side effects.
- `PROJECT_MUTATION`: Alters project artifacts or blueprints through revision-controlled services.
- `RUN_CONTROL`: Submits or cancels asynchronous pipeline runs.
- `EXTERNAL_GENERATION`: Reserved for external asynchronous media synthesis.
- `ADMIN`: Reserved for platform-level management operations; strictly requires administrative authority.

## 5. Schema Exposure for Context Builder
Tools exposed to models via Context Builder (`ToolRegistry.get_schemas()`):
- Are sorted alphabetically in deterministic order (`name`).
- Strictly exclude disabled tools (`enabled=False`).
- Strictly omit privileged identity fields from input schemas.
- Are packaged into `ContextSection.TOOLS` with `ContextSourceType.TOOL_SCHEMA`.

## 6. Audit Policy
Every tool dispatch emits a structured `ToolAuditRecord` via `ToolAuditRecorder`:
- Records: `tool_name`, `tool_version`, `actor_id`, `workspace_id`, `target_resource`, `decision`, `side_effect_class`, `timestamp`, `duration_ms`, `status`, `error_code`.
- Secrets, API keys, passwords, bearer tokens, raw media payloads, and prompts are strictly sanitized and never recorded.
