# Phase 7.0 — Runtime Baseline

هذا المستند يوثق الوضع الحالي للعمليات التشغيلية (Logs & Behaviors) قبل تطبيق تعديلات "الضبط التشغيلي والمراقبة" (Phase 7).

## 1. مسار Pipeline العادي (Normal Pipeline)
عند تشغيل المنسق الذكي على مشروع سليم (أو خالي من الملفات التي تفعّل البوابات الأخرى):
**الأمر:** `python scripts/pipeline.py <project_id>`
**سجل التشغيل الحالي (Logs):**
```text
🔍 [المنسق الذكي] جاري تحليل حالة المشروع: prj_mock...

➔ المرحلة الأولى (Assets):
   ⏳ تشغيل asset_gate.py...
   ✅ نجاح: asset_gate.py

➔ المرحلة الثانية (Plan): ملف master_plan.md غير موجود بعد.

➔ المرحلة الثالثة (Blueprint & QC): ملف 05_blueprint.json غير موجود بعد.

🎉 انتهى الفحص بنجاح! جميع ملفاتك وحالتك الحالية سليمة 100%.
```
**مكان الحفظ:** يظهر في الـ standard output فقط.
**ملاحظة على الوضع الحالي:** لا يوجد Request ID ولا تصنيف للحدث (Structured Logging).

## 2. مسار فشل بوابات (Gate Failure)
عند فشل إحدى بوابات الـ Pipeline (مثلاً المرحلة الأولى):
**الأمر:** `python scripts/pipeline.py <project_id>`
**سجل التشغيل الحالي (Logs):**
```text
🔍 [المنسق الذكي] جاري تحليل حالة المشروع: prj_mock...

➔ المرحلة الأولى (Assets):
   ⏳ تشغيل asset_gate.py...
   ❌ فشل في asset_gate.py
======================================== تفاصيل الخطأ ========================================
(Traceback and error details...)
==============================================================================================

🛑 توقف التنفيذ بسبب أخطاء في المرحلة الأولى. أصلح المشاكل وأعد التشغيل.
```
**ملاحظة على الوضع الحالي:** الخطأ يطبع كنص حر، لا يوجد Error Code ولا تصنيف موحد لنوع الفشل.

## 3. مسار Render العادي والفشل المتعمد (Render Normal & Intentional Failure)
الـ Render يتم عبر `render_project.py` الذي يتأكد من حالة الموافقة (Lock) قبل التشغيل.
**الأمر:** `python scripts/render_project.py <project_id>`
**سجل التشغيل الحالي لفشل الحماية (Guardian Block - Intentional Render Failure):**
```text
✅ جاري التحقق من المشروع prj_mock...

============================================================
🛑 [GUARDIAN BLOCK] ممنوع الرندر!
============================================================
لم يتم إصدار موافقة بشرية على المشروع (status != locked)
```
**سجل التشغيل لـ Render عادي (ناجح):**
```text
✅ جاري التحقق من المشروع <project_id>...
🎥 جاري الرندر (محلي)...
(Remotion output stream...)
✅ نجاح الرندر! تم حفظ الفيديو في: <output_file>
```
**ملاحظة على الوضع الحالي:** مخرجات Remotion تدمج مع مخرجات بايثون دون تتبع واضح لمعرف المهمة (Run ID) مما يصعّب تتبع الفشل عند تشغيله خلف واجهة برمجية.

## 4. مسار استدعاء واجهة برمجة التطبيقات (API Request)
عند إرسال طلب للـ API، يتم تشغيل العمليات في الخلفية. 
**سجل التشغيل الحالي (Logs):**
تعتمد الـ API على طباعة الأخطاء العادية عبر `FastAPI` أو `uvicorn`.
```text
INFO:     127.0.0.1:51234 - "POST /api/v1/projects/<id>/render HTTP/1.1" 202 Accepted
```
**ملاحظة على الوضع الحالي:** لا يوجد Correlation ID يربط بين استدعاء الـ API ومخرجات الـ Pipeline أو الـ Render في الخلفية.

## الخلاصة وتقييم نقطة الأساس
- **كيف يبدو النجاح والفشل حاليًا؟** يعتمد على طباعة نصوص ملونة (stdout) مقروءة للبشر، ولكنها غير منظمة آلياً (Unstructured).
- **إمكانية التتبع (Traceability):** شبه معدومة. يصعب ربط طلب API بسجل Pipeline وبفشل Render.
- **التشخيص التلقائي:** صعب، حيث يتطلب قراءة الـ Traceback يدوياً.

**بوابة الخروج لـ Phase 7.0 ✅:** تم توثيق الوضع الحالي، وجاهزون لبدء Phase 7.1 (Structured Logging).
