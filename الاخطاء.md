## 1. Executive Summary

The system is an AI-driven video production factory comprising a Python/FastAPI backend, a Remotion (React) rendering engine, a multi-stage quality pipeline, and an Agentic AI workspace (`.agents/` with MCPs and plugins). Following a **complete 5-phase architectural autopsy covering 100% of the codebase**, it was discovered that the system suffers from **severe architectural drift, zombie code, instruction schisms, and critical security/stability vulnerabilities** due to multiple undocumented refactoring cycles.

## 2. Architectural Findings by Subsystem

### Phase 1: Critical Priority (Parallel System Detection)

#### A. The Pipeline Schism (CRITICAL)
*   **Two Parallel Pipelines Exist:**
    *   `scripts/pipeline.py` - The **official** system used by the AI agent via CLI, uses hash-based state in `.pipeline_state.json`
    *   `scripts/core/pipeline.py` - A **zombie** system called by the API/GUI, uses `UnifiedPipeline` class with numbered gates (1,2,3) in `state.json`
*   **The Two Worlds Never Intersect:** The GUI and the AI agent live in completely different architectural worlds. The GUI thinks the project is at "Gate 1" while the AI agent might be at the final render stage.
*   **State Management Conflict:** Official uses Hash-based `.pipeline_state.json`, Zombie uses numbered gates in `state.json`.

#### B. The Zombie Gate System
*   `scripts/gates/` contains `checks.py`, `plan_report.py`, `stage_gate.py` - a completely different gate system from the official `asset_gate.py`, `plan_gate.py`, `taste_gate.py`.
*   `plan_report.py` attempts to **auto-generate** the Master Plan, directly violating the `AGENTS.md` rule: *"The agent writes the plan"*.

#### C. The API Services Layer
*   `api/services/render_service.py` imports `UnifiedPipeline` from the zombie system instead of calling the official `scripts/pipeline.py`.
*   `api/services/gate_service.py` writes to `state.json` instead of reading from `.pipeline_state.json`.

---

### Phase 2: High Priority (Engine & Contracts)

#### D. The Zombie Engine (CRITICAL)
*   **The Entire `engine/` Directory is Disconnected:**
    *   `engine/camera` (CameraRig, AutoZoom) - Never imported
    *   `engine/cursor` (CursorSprite) - Never imported
    *   `engine/layout` (LayoutProvider) - Never imported
    *   `engine/primitives` (17 UI components) - Never imported
*   **The Smoking Gun:** In `BlueprintVideo.tsx` line 20:
    ```tsx
    const EngineBridge = ({ children }) => <>{children}</>;
    ```
    The bridge that was supposed to connect camera and layout has been **gutted** into a dummy component.

#### E. The Contracts Schism
*   **Living Contracts:** `contracts/blueprint.ts` contains real Zod Schemas used in `merge.ts` for runtime validation.
*   **Dead Schemas:** `schemas/*.json` files are empty stubs containing only descriptions, not reflecting actual data structures.
*   **The Fix:** Replace JSON schemas with auto-generated exports from Zod schemas using `zod-to-json-schema`.

#### F. The Template Registry
*   `registry/template-registry.tsx` is the **single source of truth** for templates.
*   87 templates registered, 87 templates exist - **perfect 1:1 match**.
*   However, the registry is 1200+ lines of manual imports that should be auto-generated.

### Phase 3: Medium Priority (Templates & Content)

#### G. The Template Library (PRAISE)
*   **87 templates, all alive, all registered, perfect 1:1 match.**
*   No orphaned templates, no ghost templates.
*   This is the cleanest part of the entire system.

#### H. The Recipe System (PRAISE)
*   **20 recipes, all valid, all schema-compliant.**
*   Recipes are designed to be **template-agnostic** - they don't reference specific templates, making them resilient to template changes.

#### I. The Primitives Graveyard
*   **119 primitives exist, only 7 are used, 112 are zombies.**
*   The primitives are never imported by the living scenes or templates.
*   This is a massive "UI library" that was imported but never utilized.

### Phase 4: Security & Tools

#### J. The RCE Vulnerability (CRITICAL)
*   **`Video_Editor_MCP` contains an `execute_command` tool** that passes commands directly to subprocess without any filtering.
*   This allows the AI agent to execute arbitrary commands, bypass all guards, and access any file on the system.
*   **The Fix:** Delete `Video_Editor_MCP` immediately and use the safe `ffmpeg-mcp-server` instead.

#### K. The Rebel Workflows (CRITICAL)
*   **All 4 workflows in `workflows/` are rebel agents:**
    *   `avatar-insta-split/` - Manually composites video with FFmpeg, bypasses Pipeline
    *   `avatar-vo-broll/` - Creates video in one step, bypasses gates
    *   `tabletop-levels-explainer/` - Teaches future agents to bypass protocol
    *   `living-canvas-explainer/` - Abandoned project
*   These workflows teach AI agents to **rebel against the official protocol**.

#### L. The Zombie Tools
*   5 standalone tools conflict with the new architecture:
    *   `demo_video_composer.py` - Manual compositing (banned)
    *   `local_explainer_broll.py` - Ad-hoc code generation (banned)
    *   `video_orchestrator.py` - Replaced by `pipeline.py`
    *   `ugc_ad_runner.py` - Old recipe system
    *   `video_recipes.py` - Old plan system

#### M. The MCP Security Issues
*   `media-sources-mcp` has a hardcoded wrong path (`c:\video\video-workspace\assets`) and accepts `custom_path` without sanitization (Path Traversal risk).
*   `audio-tools-mcp` actually checks LUFS properly (-16, -24) - **this is good news**.
*   `ffmpeg-mcp-server` is safe and restricted - **this is the correct alternative**.

#### N. The Test Coverage
*   **Good:** Pipeline tests, Guardian tests, API tests exist and are comprehensive.
*   **Missing:** MCP security tests, standalone tool tests.
*   **Zombie:** `test_transcript_cleaner.py` tests a dead system.
